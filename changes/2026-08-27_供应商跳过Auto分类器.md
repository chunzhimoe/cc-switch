# 供应商级跳过 Auto 分类器

## 背景与根因

现有 `meta.classifierRouting` 只负责给 Claude Code Auto 安全分类器选择模型：本地代理路径按 marker 改写请求，外部直连路径投影 `CLAUDE_CODE_AUTO_MODE_MODEL`。它仍会实际执行分类器请求，无法满足“已经接受 `dangerously-skip-permissions` 风险、希望直接不进入 Auto 分类”的供应商级使用方式。

本次采用 Claude Code live settings 的正式权限配置，而不是在 CC Switch 代理中伪造分类器响应：供应商启用高风险开关后，写入 `permissions.defaultMode = "bypassPermissions"`，同时保持 `sandbox.enabled = true`。这样外部 URL 直连和本地代理使用同一语义，也避免合成响应格式随 Claude Code 版本变化。

## 行为差异

### 修改前

- 分类器分流只能更换分类器模型，请求仍会发送和执行。
- 无法按供应商保存 `sandbox + bypassPermissions` 的高风险权限配置。
- 外部直连若需要避开 Auto 分类，只能由用户手工维护 live settings 或启动参数。

### 修改后

- 每个 Claude 供应商可独立启用“跳过 Auto 分类器（高风险）”。
- 保存并切换供应商后，live settings 同时启用 sandbox 和 `bypassPermissions`。
- 外部直连与本地代理行为一致，不依赖代理 marker 短路。
- 切走供应商时不会把注入字段固化到 `settingsConfig`，也不会污染下一供应商。
- 原有分类器分流模型列表继续保存，但跳过开启期间不会生效。
- 必须完全重启 Claude Code，已运行会话不会重新读取 live 权限配置。

## 已知风险与后续事项

- 该开关明确降低 Claude Code 的逐操作安全检查能力；UI 使用 destructive 二次确认并持续显示风险。
- `sandbox.enabled = true` 不等于恢复逐操作审批；`bypassPermissions` 仍允许高风险操作直接执行。
- 启动时显式传入其他 permission mode 可能覆盖 live 设置；使用该开关后应完整重启并确认实际启动参数与目标模式一致。
- 如果 `permissions` 或 `sandbox` 在低级 JSON 中被写成非对象，后端会记录 warning 并拒绝覆盖该异常节点，避免静默破坏原始数据。
- Rust 代码尚未在本机编译，是合并/发布前的主要剩余验证风险。
