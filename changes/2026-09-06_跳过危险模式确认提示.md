# 跳过危险模式确认提示

## 背景与根因

供应商级“跳过 Auto 分类器”原本只向 Claude Code live 配置注入：

- `permissions.defaultMode = "bypassPermissions"`
- `sandbox.enabled = true`

用户要求该显式高风险开关开启时，同时写入根级 `skipDangerousModePermissionPrompt = true`，使配置与界面所表达的跳过行为一致。默认关闭状态及其他供应商不受影响。

## 修改文件与核心符号

- `src-tauri/src/services/provider/live.rs`
  - `apply_claude_auto_classifier_bypass` 新增根级参数投影。
  - `strip_injected_claude_auto_classifier_bypass` 在切走或关闭开关时恢复供应商原值；仅在 live 仍为注入值 `true` 时处理，用户手改为其他值时不覆盖。
  - `strip_common_config_from_live_settings` 在剥离通用配置前先恢复注入值，避免供应商显式原值被共同片段误删。
  - 新增 `prepare_claude_common_config_for_sync`，以供应商和当前 common snippet 的合并结果为基线，在学习共享偏好前恢复三个注入字段。
- `src-tauri/src/services/provider/mod.rs`
  - `sync_common_config_snippet_from_live` 对 Claude 使用上述预处理，防止 `bypassPermissions`、sandbox 和危险模式提示参数污染所有供应商的通用配置。
- `src/components/providers/forms/AutoClassifierBypassField.tsx`
  - 描述和 destructive confirmation 明确列出新增参数及效果；启用仍需确认，关闭仍立即生效。
- `src/i18n/locales/{zh,en,ja,zh-TW}.json`
  - 四语言同步新增参数说明和风险确认内容。
- `tests/components/AutoClassifierBypassField.test.tsx`
  - 四语言参数披露和确认弹窗断言。

## 真实调用链

- 普通直连写入：`write_live_with_common_config` → `build_effective_settings_with_common_config` → `write_live_snapshot`。
- 代理运行中的当前供应商同步：`sync_claude_live_from_provider_while_proxy_active` 使用相同的有效配置构建入口。
- 代理接管备份更新：`update_live_backup_from_provider` 同样使用该入口，因此关闭代理后恢复的配置也保留该显式开关效果。
- 切换供应商时：先恢复 live-only 注入，再回填供应商和同步 common snippet，避免把派生值固化进数据库。

以上调用链在用户明确授权后使用外部代码索引辅助核验；未发送本机凭据或运行时配置。

## 行为差异（修改前 → 修改后）

- 开启开关：注入两个字段 → 注入三个字段，新增根级 `skipDangerousModePermissionPrompt = true`。
- 关闭或切走：只恢复 permissions/sandbox → 同时恢复或删除新增根字段。
- 共享配置同步：可能学习 live-only 注入值 → 先按 provider + common snippet 基线恢复，再提取共享偏好。
- 用户在 live 中把注入字段改成非注入值时，回填不会覆盖该手动修改。
