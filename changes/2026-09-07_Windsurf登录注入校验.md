# 2026-09-07 Windsurf 登录注入校验

## 背景与根因

macOS 上用邮箱密码添加账号后，CC Switch 提示“登录态已写入，已启动”，但 Devin 打开仍是 Login。已核验的代码缺陷（不是客户端键名错误）：

1. Auth1 刷新把 IDE token 写入 `windsurf_auth_token` / `sessionToken`，真正的 PostAuth session 被解析器丢掉。
2. 切号不刷新长期 auth1，反复注入过期短期凭据。
3. 每次写入 `windsurf.pendingApiKeyMigration`，客户端启动时优先用它并反写 sessions。
4. macOS Keychain 查询允许 Devin→Windsurf 跨品牌回退；`--user-data-dir` 会跳过官方品牌迁移。
5. 回读只检查 `v10` 前缀，任意密文都能报“写入成功”。

- `src-tauri/src/windsurf/account.rs` — session / IDE 字段分离；切号前 `refresh_account_for_switch`

## 行为差异（修改前 → 修改后）

- 邮箱密码账号：IDE token 当作 session 注入 → PostAuth session 写入 `sessions[].accessToken` 与 `apiKey`
- 切号：直接用磁盘上的短期凭据 → 有 auth1 时先刷新，失败不关客户端、不写 live、不改 current
- Keychain：跨品牌回退 → 仅目标 `${nameLong} Key`，失败即停
- pending migration：每次写入覆盖通道 → 显式删除该键
- 校验：`v10` 前缀即可 → COMMIT 前解密比较 session / URL / 选中账号 / 扩展 state
- 成功 toast：不再暗示客户端已登录，只声明“会话写入已校验…请在客户端确认账号”
- 通用 provider/tray：macOS 仍要求客户端已停止，不新增自动杀进程
