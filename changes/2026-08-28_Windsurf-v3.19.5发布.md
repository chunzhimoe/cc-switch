# Windsurf v3.19.5 发布候选归档

## 背景与目标

本次候选版本在 `v3.19.4-windsurf.1` 基础上继续完善 Windsurf/Devin 集成，目标是：

1. 将 Windsurf 纳入统一 Skills 管理、同步和应用启用状态。
2. 为 Windsurf 用户数据、Skills、MCP 和 Rules 提供可配置的目录覆盖。
3. 在 macOS 上实现账号切换所需的 Chromium/Electron Safe Storage 写入。
4. 将应用、Tauri crate 与 Cargo lockfile 版本统一升级到 `3.19.5`，并准备 `v3.19.5-windsurf.1` 预发布标签。

## 版本与依赖

- `package.json`：`3.19.4` → `3.19.5`。
- `src-tauri/Cargo.toml`：crate 版本同步为 `3.19.5`；保留 `windsurf/process.rs` 实际使用的 `sysinfo = "0.33"` 直接依赖。
- `src-tauri/tauri.conf.json`：Tauri 应用版本同步为 `3.19.5`。
- `src-tauri/Cargo.lock`：`cc-switch` package 版本同步为 `3.19.5`；补齐 macOS `cbc 0.1.2`、`aes`、`pbkdf2`、`sha1`、`zeroize`，同时补齐既有 Windows `aes-gcm 0.10.3`、`windows 0.58.0` 及其传递锁项，并启用 `inout` 的 `block-padding` 锁依赖；恢复 `sysinfo 0.33.1` 对应的 `rayon`、`ntapi` 与 `windows 0.57.0` 完整锁闭包。
- 目标标签：`v3.19.5-windsurf.1`。

## 后端变更

### Skills 与数据库

- [app_config.rs](../src-tauri/src/app_config.rs) 将 `SkillApps.windsurf` 纳入启用判断、设置、空状态和启用应用列表，移除 Windsurf 的硬编码禁用分支。
- [services/skill.rs](../src-tauri/src/services/skill.rs) 将 Windsurf 接入正常 Skills 目录同步，使用 `windsurf::paths::skills_dir()`，支持现有 symlink/copy 流程。
- [database/mod.rs](../src-tauri/src/database/mod.rs) 将 `SCHEMA_VERSION` 从 17 提升到 18。
- [database/schema.rs](../src-tauri/src/database/schema.rs) 为 `skills` 增加 `enabled_windsurf BOOLEAN NOT NULL DEFAULT 0`，并提供 v17 → v18 的幂等迁移。
- [database/dao/skills.rs](../src-tauri/src/database/dao/skills.rs) 在查询、保存和更新中加入 Windsurf 列；单条查询的列索引同步修正，避免 `installed_at`、`content_hash` 和 `updated_at` 读取错位。
- 新增数据库往返测试和 v17 → v18 迁移测试，覆盖 Windsurf 标志及后续元数据列。

### 目录覆盖与路径解析

- [settings.rs](../src-tauri/src/settings.rs) 新增并规范化：
  - `windsurf_user_data_dir`
  - `windsurf_skills_dir`
  - `windsurf_mcp_dir`
  - `windsurf_rules_dir`
- [windsurf/paths.rs](../src-tauri/src/windsurf/paths.rs) 支持 user-data 候选选择、Skills 默认目录 `~/.codeium/windsurf/skills`、Rules 默认目录 `~/.codeium/windsurf/memories`，并优先使用显式覆盖。
- [mcp/windsurf.rs](../src-tauri/src/mcp/windsurf.rs) 优先从 `windsurf_mcp_dir/mcp_config.json` 读取，否则回落到平台配置目录下的 `devin/mcp_config.json`。
- 前后端默认 MCP 路径统一使用平台 `configDir`/`dirs::config_dir`，避免把 Tauri 应用自身的 bundle-specific `appDataDir` 错当作 Windsurf 配置根目录。

### macOS SecretStorage

- [windsurf/auth_write.rs](../src-tauri/src/windsurf/auth_write.rs) 增加独立 macOS 分支：
  - 通过 `/usr/bin/security` 在进程内读取 Devin/Windsurf Safe Storage Keychain 条目。
  - 按 profile 品牌优先查询，并保留另一品牌候选作为回退。
  - 使用 PBKDF2-HMAC-SHA1（`saltysalt`、1003 次）派生 16-byte AES key。
  - 使用 AES-128-CBC、PKCS#7、16 个 ASCII 空格 IV，输出 `v10` 前缀密文。
  - 仅剥离命令行追加的一层换行，不删除合法首尾空格。
  - 用 `zeroize::Zeroizing` 清理派生 key、明文缓冲区和 Keychain 密码。
  - 现有 `v11` 数据明确拒绝写入，避免未知格式被静默降级覆盖。
- Windows DPAPI + AES-256-GCM 路径保持不变；Linux/其他平台仍返回平台不支持错误。
- 账号注入调用方 [windsurf/inject.rs](../src-tauri/src/windsurf/inject.rs) 已使用 `BEGIN IMMEDIATE`、失败 `ROLLBACK`、成功 `COMMIT` 包住整组 state.vscdb 更新，本候选不嵌套第二个事务。
- macOS 实现已在最终工作树中独立重写，不直接复制 `cockpit-tools` 源码；后者仅作为互操作参数和历史 Keychain 候选的参考。

## 前端变更

- [src/App.tsx](../src/App.tsx) 与 [src/config/appConfig.tsx](../src/config/appConfig.tsx) 开放 Windsurf Skills/MCP 入口。
- [useDirectorySettings.ts](../src/hooks/useDirectorySettings.ts)、[DirectorySettings.tsx](../src/components/settings/DirectorySettings.tsx) 和 [SettingsPage.tsx](../src/components/settings/SettingsPage.tsx) 增加四类 Windsurf 目录的加载、浏览、重置、覆盖和展示；当 settings 异步加载或覆盖值后续变化时，会单独同步四个 Windsurf resolved 值，避免界面长期显示默认目录。
- [useSettings.ts](../src/hooks/useSettings.ts)、[useSettingsForm.ts](../src/hooks/useSettingsForm.ts) 和 [types.ts](../src/types.ts) 补齐字段类型、清理和保存链路。
- [WindsurfAccountsPanel.tsx](../src/components/windsurf/WindsurfAccountsPanel.tsx) 将 app path/user-data path 从只读状态改为可编辑字段，在失焦时静默保存并显示成功提示。
- 英文、简体中文、繁体中文和日文 locale 增加目录设置与保存提示文案。

## 发布前风险与手工验证

1. macOS 首次访问 Safe Storage 可能出现 Keychain 授权对话框，需要用户允许。
2. 需要在真实 Devin、Windsurf、双品牌并存和自定义 user-data 目录上验证切换 → 重启 → 回切闭环，并确认密文可被目标客户端解密。
3. 自定义目录名称不含品牌时，Keychain 查询优先级采用 Devin 默认顺序，但仍会遍历另一品牌候选。
4. `v11` SecretStorage 写入尚未实现；遇到现有 v11 数据会安全失败而不是静默写入 v10。
5. Linux SecretStorage 写入仍未实现。
6. 本机没有 Cargo，Cargo.lock 依据相同版本的 registry checksum/依赖块手工补齐，并通过脚本检查 manifest 直接依赖与 lock root 完全一致、所有 lock 依赖引用均可解析；仍必须以 CI 的 Cargo resolver、编译和格式检查为最终依据。
