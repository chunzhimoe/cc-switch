# 供应商 Auto 模式分类器分流

## 背景和根因

此前 CC-Switch 没有针对 Claude Code Auto 模式安全分类器请求的供应商级分流配置。主对话虽然可以通过供应商的普通模型映射发送到 new-api 等渠道，但 Auto 分类器请求会继续携带原始 `model`，导致中转站将分类器请求路由到不可用或不适合的模型。

Claudish 的可靠判断方式是检查 Claude Messages 请求的 `system` 内容是否以固定 marker 开头，而不是依据 `max_tokens`、system 长度等启发式字段。

## 存储结构

配置存储在 SQLite `providers.meta` JSON 中，不进入 `settingsConfig`，因此不会写入 Claude live `settings.json`：

```json
{
  "meta": {
    "classifierRouting": {
      "enabled": true,
      "strategy": "priority_list",
      "defaultModel": "gpt-5.6-sol",
      "logHits": true,
      "models": [
        {
          "id": "gpt-5.6-sol",
          "note": "稳定",
          "inputPrice": 2.5,
          "outputPrice": 12.5
        }
      ]
    }
  }
}
```

旧供应商没有该字段时反序列化为 `None`，保持关闭和原有行为；不需要数据库 schema migration。

## 行为变化

### 修改前

- 供应商只有普通 Claude 模型映射。
- Auto 安全分类器请求无法按供应商选择独立的真实模型。
- 不同 new-api 供应商之间无法保存不同的分类器分流规则。

### 修改后

- 在 Claude 供应商编辑页的高级选项中配置分类器分流。
- 只有当前实际路由到该 provider 且命中 marker 时才改写 `model`。
- 普通主对话继续使用原有模型映射。
- 命中后删除顶层 `thinking`，降低换模型导致的 400 风险。
- `fixed` 使用默认模型。
- `priority_list` 使用列表第一项；本期不做列表内失败重试。
- `cheapest` 在输入/输出单价都完整且有效的条目中选择 `input + output` 最小者；缺价时回退默认模型和列表第一项。
- 通用 `localProxyRequestOverrides.body` 不能覆盖分类器最终模型，也不能重新启用顶层 `thinking`。
- `logHits` 开启时输出 provider、改写前和改写后的模型。

## Claudish marker 检测边界

检测常量：

```text
You are a security monitor for autonomous AI coding agents.
```

支持：

- `system` 为字符串且忽略 ASCII 前导空白后以 marker 开头。
- `system` 为数组，扫描全部 block。
- 裸字符串 block 和 `{ type: "text", text: "..." }` block。
- 第一个 billing header block 后面的 marker。

拒绝：

- 主 Claude Code system prompt。
- marker 位于 block 中间。
- 缺失、空数组、错误类型和非 text block。
