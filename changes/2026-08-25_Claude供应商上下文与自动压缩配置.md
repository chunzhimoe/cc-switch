# Claude 供应商上下文与自动压缩配置

## 背景与根因

Claude 供应商编辑器此前没有可视化配置 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`、`CLAUDE_CODE_AUTO_COMPACT_WINDOW` 和顶层 `autoCompactWindow`。历史供应商缺少这些字段时，也没有统一的保存默认值和类型约束，无法稳定地向 Claude Code 声明第三方模型的 400K 上下文上限及自动压缩窗口。

## 修改内容

- `src/components/providers/forms/hooks/useClaudeCompactWindowState.ts`
  - 新增 `DEFAULT_CLAUDE_CONTEXT_WINDOW = "400000"`。
  - 新增三值解析、正整数校验、独立状态更新和 `applyClaudeContextWindowConfig` 保存归一化。
  - 两个环境变量按字符串保存，顶层 `autoCompactWindow` 按数字保存。
- `src/components/providers/forms/ClaudeFormFields.tsx`
  - 在高级选项中新增“上下文与自动压缩”区域。
  - 提供三个互不联动的数字输入框，并展示各自实际写入位置。
- `src/components/providers/forms/ProviderForm.tsx`
  - 监听 `settingsConfig` 以支持预设切换和原始 JSON 编辑后的回填。
  - 提交前校验三个值均为安全的正整数。

## 行为变化

### 修改前

- 编辑供应商无法直接设置上述三个字段。
- 新建或既有供应商缺少字段时不会自动补齐。
- 顶层 `autoCompactWindow` 可能进入 Claude 公共配置片段。

### 修改后

- 三个字段独立配置，默认均为 400000：
  - `CLAUDE_CODE_MAX_CONTEXT_TOKENS` → `env` 字符串，强制向 Claude Code 声明模型上下文上限为 400K。
  - `CLAUDE_CODE_AUTO_COMPACT_WINDOW` → `env` 字符串。
  - `autoCompactWindow` → `settings.json` 顶层数字。
- 既有 Claude 供应商缺少这些字段时，编辑保存后会自动补齐默认值。
- 三个字段互不联动，用户可以分别调整；空值、0、非整数或超出 JavaScript 安全整数范围的值会阻止保存。
- `autoCompactWindow` 不再进入公共配置片段。

## 已知风险与后续事项

- Rust 侧仅进行了最小常量列表和测试断言修改，仍需在具备 Rust 工具链的环境补跑 `cargo fmt --check` 与相关 `cargo test`。
- 现有 Kimi For Coding、Codex OAuth 等预设已经显式定义其他上下文值；编辑保存时会保留这些显式值，仅对缺失字段使用 400000 默认值。
- `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 对特定 Claude 原生模型 ID 的实际生效规则仍由 Claude Code 决定，本次主要面向第三方/映射模型场景。
