# Auto 分类器外部直连启用修复

## 背景与根因

供应商级 `meta.classifierRouting` 的保存、反序列化和本地代理改写链路原本均可工作，但启用效果依赖请求进入 cc-switch 的 `RequestForwarder`。当 Claude Code 的 `ANTHROPIC_BASE_URL` 指向外部上游时，请求直接离开 Claude Code，不经过本地代理，因此分类器配置没有执行机会，Auto 安全判断仍可能使用 Sonnet 等普通角色映射中的模型。

代理模式另有一个独立漏判：Claude Code 可能把 `x-anthropic-billing-header:` 与安全分类器 marker 放在同一个 `system` 字符串或 text block 中。原来的严格 `starts_with(marker)` 无法识别这种形态。

## 修改文件与核心符号

### 直连外部 URL

- `src-tauri/src/services/provider/live.rs`
  - 新增 `CLAUDE_CODE_AUTO_MODE_MODEL_ENV`。
  - 新增 `apply_claude_auto_mode_model`：
    - 从当前 Claude 供应商的 `meta.classifierRouting` 读取配置；
    - 复用 `pick_classifier_model` 执行 `fixed` / `priority_list` / `cheapest` 选择；
    - 将派生模型写入有效 Live 配置的 `env.CLAUDE_CODE_AUTO_MODE_MODEL`；
    - 不修改 `ANTHROPIC_BASE_URL`，因此外部直连不需要本地代理；
    - 供应商 `settingsConfig.env` 中显式填写的同名值优先，不被派生值覆盖。
  - 在 `build_effective_settings_with_common_config` 的 Claude 分支中应用该 Live 投影。
  - 新增 `strip_injected_claude_auto_mode_model`，在 `restore_live_settings_for_provider_backfill` 中剥离派生值，避免切走供应商时把 Live 投影固化进 `settingsConfig`；如供应商原本有显式同名值则保留。
  - 增加外部 URL 保持不变、模型策略选择、Live-only 往返、显式 env 优先和空模型不注入的回归测试。

### 本地代理兼容修复

- `src-tauri/src/proxy/classifier_routing.rs`
  - 复用 `strip_leading_anthropic_billing_header`，先跳过 ASCII 前导空白并剥离首行 billing header，再严格检查安全分类器 marker。
  - 继续拒绝 marker 位于普通用户前言或文本中段的情况，避免宽泛 `contains` 误判。
  - 新增 `ClassifierRouteDecision`、`diagnose_classifier_route` 和 `classifier_system_shape`，区分 `Disabled` / `NotClassifier` / `NoModel` / `Hit`。
  - 增加 billing header 的 LF、CRLF、字符串、text block、负例和诊断分支测试。
- `src-tauri/src/proxy/forwarder.rs`
  - 使用显式诊断结果处理分类器路由。
  - `NoModel` 输出可行动 warning；`NotClassifier` 仅记录 system 类型和 block 数量。
  - 不记录 token、header、prompt、messages 或完整请求体。
  - 命中后仍在格式转换前和最终 body override 后两次强制写回分类器模型并删除顶层 `thinking`。

### 前端与文案

- `src/components/providers/forms/ClassifierRoutingField.tsx`
  - 移除“必须启用本地代理并接管 Claude”的按钮和状态判断。
  - 明确外部 API URL 可直连，保存供应商后通过 `CLAUDE_CODE_AUTO_MODE_MODEL` 生效。
  - 提示已运行的 Claude Code 必须完整重启，现有会话不会重新读取环境配置。
  - 保留启用但无可选模型时的即时错误提示。
  - 将 `logHits` 文案明确为仅本地代理命中日志。
- `tests/components/ClassifierRoutingField.test.tsx`
  - 移除 `useProxyStatus` mock 和接管按钮测试。
  - 增加外部直连、重启提示、无模型警告及添加模型后警告消失的测试。
- `src/i18n/locales/{zh,zh-TW,en,ja}.json`
  - 同步直连、重启、无模型和代理日志范围文案。

## 行为差异

### 修改前

- `classifierRouting` 只有请求经过 cc-switch 本地代理时才会生效。
- Claude Code 直连外部 `ANTHROPIC_BASE_URL` 时，Auto 分类器仍使用 Claude Code 自身的普通模型选择结果。
- billing header 与 marker 位于同一 system 文本块时，本地代理可能漏判。
- UI 会要求用户启用本地代理接管，与外部直连需求冲突。

### 修改后

- 保存或切换当前 Claude 供应商时，cc-switch 将选中的分类器模型投影到 Live `env.CLAUDE_CODE_AUTO_MODE_MODEL`。
- 外部 `ANTHROPIC_BASE_URL` 保持原值，不需要改为 `127.0.0.1`。
- 新启动的 Claude Code 会话由自身在构造 Auto 安全分类器请求前选择独立模型。
- 本地代理模式继续保留逐请求 marker 检测、最终覆盖和安全诊断。
- 派生环境变量不会在切换回填时污染供应商持久化配置。

## 已知风险与后续事项

- `CLAUDE_CODE_AUTO_MODE_MODEL` 在 Claude Code 启动时读取；保存配置不会改变已经运行的会话，必须完整重启 Claude Code。
- 直连模式不经过 cc-switch，因此不会产生 `logHits` 代理命中日志；该选项只对本地代理路径有意义。
- 本次只处理 Auto 模式安全分类器，未写入 `CLAUDE_CODE_BG_CLASSIFIER_MODEL`。
- 该方案依赖支持 `CLAUDE_CODE_AUTO_MODE_MODEL` 的 Claude Code 版本；已在当前安装版本中确认变量存在。
- Rust 改动尚未在本机编译，CI 结果是发布前的必要验证。
